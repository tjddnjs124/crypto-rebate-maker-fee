# 설계 원칙

## 배포 전 확인 목록

### 시장 조건

- [ ] 대상 pair의 1틱 스프레드 지속시간 비율 > 50%
- [ ] 24시간 평균 거래량이 주문 크기를 충분히 흡수
- [ ] 변동성이 전략 인벤토리 한도 내에서 관리 가능

### 거래소 조건

- [ ] Maker rebate가 VIP 등급에서 양수 (음수 maker fee가 아닌 리베이트)
- [ ] Taker fee가 maker 리베이트보다 큼 (거래소 수익 구조 정상)
- [ ] API rate limit가 초당 호가 변경 가능 횟수를 지원
- [ ] WebSocket order book update 지연이 허용 범위 내

### 인벤토리 제어

- [ ] 인벤토리 상한 Q 정의
- [ ] Avellaneda-Stoikov skew 공식 구현 또는 근사
- [ ] 인벤토리가 Q에 도달하면 해당 방향 호가 중단
- [ ] 체결 후 재호가 지연 시간 정의

### 체결 확률

- [ ] 1틱 내측 체결률 측정 (데이터 기반)
- [ ] 큐우선도 보정 계수 추정
- [ ] 스프레드 상태 (1틱, 2틱, locked)별 체결률 구분

### Adverse Selection

- [ ] Realized spread 측정 pipeline 구축
- [ ] 선물-현물 lead-lag 신호 모니터링 (해당하는 경우)
- [ ] 대형 주문 감지·대응 규칙

### Spoofing

- [ ] 큐 불균형 급변 감지
- [ ] 취소율 급증 감지
- [ ] 대량 주문 등장 시 체결 일시 중단 규칙

### 인프라

- [ ] 체결 이벤트 real-time 처리 지연 목표 (< 10ms)
- [ ] 호가 변경 rate limit 준수
- [ ] 장애 시 전체 포지션 청산 경로

## 설계 철학

1. **리베이트는 수익원이지만 인벤토리는 리스크원.** 두 힘의 균형이 핵심이다.
2. **체결이 많다고 좋은 것이 아니다.** 정보 거래자와의 체결은 손해다.
3. **티크 제약이 존재 근거다.** 스프레드가 1틱에서 자유롭게 벌어지면 이 전략은 성립하지 않는다.
4. **조작을 방어 비용에 포함한다.** 규제가 약한 시장에서 spoofing은 선택이 아니라 필수 고려사항이다.
